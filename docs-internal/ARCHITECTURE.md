# Architecture

What Titrate is and how it works. For how to change it, see [WORKFLOW.md](WORKFLOW.md).
For traps that cost real time, see [GOTCHAS.md](GOTCHAS.md).

## 1. What this project is

Titrate is a personal fork of **GLPal**, an abandoned open-source GLP-1 dose and
weight tracking PWA. **There is no source tree.** The app is the deployed
minified production bundle, modified by a chain of deterministic, SHA-gated
Python patch scripts. Every change is a surgical string replacement in one
minified JavaScript file, and the whole chain reproduces byte-for-byte from a
pinned upstream capture.

Requirements that shaped it, all stated by Marc and all still binding:

- PWA, installable, works offline after install
- No account, no sign-up
- Health records local to the device (IndexedDB), no cloud dependency
- Dose records editable and deletable after entry — the specific upstream flaw
  that motivated the fork
- Simple, GLPal-like workflow
- Export/backup without forcing cloud storage

## 5. Data layer

Database name is **`GLPalDB`** and must never change. Renaming it orphans Marc's
real data; the name is devtools-only and not user-visible, so the rebrand
condition does not reach it.

```js
super("GLPalDB");
this.version(1).stores({
  weights:           "date",
  medications:       "[date+medication], date, medication",
  protocols:         "id, medication, startDate",
  peptides:          "id, category, isActive",
  peptideLogs:       "id, peptideId, date",
  userProfile:       "++id",
  medicationStorage: "id, medicationName, category, isActive",
  dailyLogs:         "date"
});
```

The browser reports native IndexedDB version 10 while Dexie declares
`version(1)`. That is normal Dexie behaviour, not a mismatch.

**Nothing derived is ever stored.** There is no level, concentration or series
in any store. Every chart point and every card value is recomputed at render
time from the raw dose records.

### Dose record

```js
{ date,            // "YYYY-MM-DD" — part of the primary key
  time,            // "HH:MM" (Log Dose form pre-fills the time it opened) — placement of the dose since patch 22, see §7
  medication,      // string — part of the primary key
  dose,            // mg
  halfLifeHours,
  isManual,        // true for manually logged doses
  painLevel, injectionSite, isr, sideEffects, notes }
```

`sideEffects` is an array of `{name, severity}`.

**The compound key `[date+medication]` is the central fact for editing.**
Changing either field changes the primary key, so an edit is delete-then-put in
one Dexie transaction. That is what `__glpalUpdateDose` does.

### Persistence primitives

| symbol | role |
|---|---|
| `Gf` | upsert a dose by scanning for a matching `date`+`medication`, then `bulkPut` |
| `xW` | delete a dose. **Upstream deleted from `weights`** — a real bug, fixed in patch 1 |
| `__glpalUpdateDose` | ours: in one `rw` transaction, delete the old compound key if it changed, then `put({...new, isManual:true})` |
| `Bc` / `Es` | reload doses into state |
| store actions | `addDose`, `updateDose` (ours), `deleteDose`, `refreshDoses` |

## 7. Medication level model

`v1(doses, halfLifeHours, sampleDate)` is the single source of truth. It is
called by the Current Level card (`zge`), by both loops in the dose-chart series
builder (`Vge`). Those are its only three callers; patch 23 removed a fourth,
unused one in the dosing-plan hook `Wye`.

### Shipped code (patch 20)

```js
__glpalTmax = t => ({168:48,127:24,120:24,108:48,13:11})[t] || Math.min(48, Math.max(6, .2*t)),
__glpalKa = (() => { const c = {}; return (k, m) => { const y = k+"|"+m; if (c[y]) return c[y];
  let l = k*1.000001, h = k*1e3; for (let j = 0; j < 80; j++) { const x = (l+h)/2;
  Math.log(x/k)/(x-k) > m ? l = x : h = x } return c[y] = (l+h)/2 } })(),
v1 = (r, t, e) => { const T = t > 0 ? t : 168, K = Math.LN2/T,
  m = Math.min(__glpalTmax(T), .95/K), A = __glpalKa(K, m),
  F = O => O < 0 ? 0 : A/(A-K)*(Math.exp(-K*O) - Math.exp(-A*O)), pk = F(m);
  return r.reduce((n, i) => n + i.dose*F((e.getTime() - i.date.getTime())/36e5)/pk, 0) }
```

### The math

One-compartment, first-order absorption and elimination — the Bateman function —
peak-normalised.

- `ke = ln2 / halfLifeHours`; a falsy or zero half-life falls back to 168 h
  inside `v1`, which also removed the chart's old NaN gaps
- `Tmax` is looked up from the stored half-life, because Tmax is not stored on
  dose records and the preset half-lives are distinct enough to act as a
  medication key: `168→48, 127→24, 120→24, 108→48, 13→11`, otherwise
  `clamp(0.2·t, 6, 48)`, then capped at `0.95/ke` (the mathematical ceiling for
  a Bateman peak)
- `ka` is solved by memoised bisection over `[ke·1.000001, ke·1000]`, 80
  iterations, so the analytic peak time `ln(ka/ke)/(ka−ke)` lands on Tmax
- `f(o) = ka/(ka−ke) · (e^(−ke·o) − e^(−ka·o))` for `o ≥ 0` hours since the dose
- a dose contributes `dose · f(o) / f(Tmax)`, so a 1 mg dose peaks at exactly
  1 mg — this preserves the app's "mg on board" display convention
- total = sum over every dose of that medication
- the long tail is pure half-life decay, identical to the pre-patch-20 model

### Tmax decides whether patch 20 is visible at all

Measured per 1 mg dose, daily sampling, 8 weeks:

| medication | half-life | Tmax | peaks | max difference vs the old model |
|---|---|---|---|---|
| Semaglutide (Ozempic/Wegovy) | 168 | 48 h | day 2 | **0.135 mg** |
| Dulaglutide | 108 | 48 h | day 2 | visible |
| Tirzepatide (Mounjaro/Zepbound) | 127 | 24 h | day 1 | 0.034 mg |
| Retatrutide / Custom | 120 | 24 h | day 1 | 0.036 mg |
| Liraglutide | 13 | 11 h | day 1 | 0.295 mg |

A Tmax-24 Bateman curve is shape-equivalent to the old 24-hour ramp model. Two
medications with different half-lives therefore draw visibly different curve
shapes on the same chart. See GOTCHAS.

### Input sourcing

- **Half-life per medication** = `halfLifeHours` of the **earliest** dose record
  carrying that exact medication string. Later records' values are ignored.
  Two spellings of the same drug are two independent series with independently
  sourced half-lives. The card call site also has a `|| 168`.
- **Dose time** = `__glpalDoseAt(record)` (patch 22): local `date` at the
  hours and minutes of `record.time`. Accepts `H:MM`, `HH:MM`, `HH:MM:SS`,
  optionally followed by AM/PM. Missing, empty, malformed or out-of-range time
  falls back to local midnight, the pre-patch-22 behaviour. Used at both
  places that build model input: `Ege` (chart) and `zge` (card).
  The stored time is when the dose was logged unless edited, which is not
  necessarily when it was injected.
- **Sample time** = now for the Current Level card; local midnight per day on
  the chart, except today, which is sampled at the current time (patch 14).

### What the curve means

Dose time is honoured when recorded; the level curve is a population-average
one-compartment model with a fixed Tmax per medication, so values near a dose
show shape, not individual plasma concentration. Label Tmax ranges are wide —
tirzepatide 8–72 h, semaglutide 1–3 days — so the uncertainty in the curve's
shape is larger than the correction patch 22 made.

### Previous model, for reference

```js
v1 = (r,t,e) => r.reduce((n,i) => { const o = (e.getTime()-i.date.getTime())/36e5;
  if (o < 0) return n; let s;
  if (o < 24) { s = i.dose*(o/24) } else { s = i.dose*Math.exp(-.693*(o-24)/t) }
  return n+s }, 0)
```

Linear 24 h ramp, then exponential decay, with a kink at hour 24.

## 8. Chart axis model

Both charts use an ECharts **category** axis with series data given as
`[categoryValue, y]` pairs, so ECharts matches points to positions **by name**.

Since patch 21, category values are year-qualified and unique per calendar day:

```js
function __glpalDayKey(D)   { return D.toLocaleDateString("en-US",{month:"short",day:"numeric"}) + " " + D.getFullYear() }  // "Aug 30 2026"
function __glpalDayLabel(v) { return typeof v == "string" ? v.replace(/ \d{4}$/, "") : v }                                  // "Aug 30"
```

Nine sites build a category value with `__glpalDayKey`: `Pge` (axis array,
today label); `Vge` (dose-marker key, combined-series label, per-medication
label); `kge` (weight `displayDate`); `Rge` (axis array, today label,
dose-change pin label). Both `xAxis` blocks carry
`axisLabel.formatter = __glpalDayLabel`, so ticks read as before. Both tooltip
titles use the key directly — they previously appended the year by hand and
produced the same text.

Because keys are unique, `indexOf` lookups are exact. Before patch 21 they were
not, and any history longer than 365 days broke both charts.

### Series split

`Vge` walks every day from `firstDate` to `lastDate` (last dose + 60 days):

```
O = xAxisDates.indexOf(dayKey)
O <= todayIndex  ->  solid past series
O >= todayIndex  ->  dotted "_future" series      (today is in both)
```

The last element of the past series is today's level; patch 13 draws the
labelled current-level marker there.

`Vge` drops the combined series entirely when only one medication is tracked:
`[...(meds.length > 1 ? combined : []), ...perMed]`.

## 9. Date handling (patch 7)

Stored dates are `YYYY-MM-DD` strings.

**Rule: parse-for-display is local; parse-for-storage round-trips stay UTC.**

```js
function __glpalLocalDate(v) {
  if (typeof v == "string") { const m = /^(\d{4})-(\d{2})-(\d{2})$/.exec(v);
    if (m) return new Date(+m[1], +m[2]-1, +m[3]) }
  return new Date(v) }
```

`new Date("2026-08-10")` parses as UTC midnight, so `toLocaleDateString` in the
Americas shows the previous day. Only expressions feeding `toLocaleDateString`
were changed. Sites doing `new Date(s) → setTime → toISOString().split("T")[0]`
are UTC-in/UTC-out and correct; localising them would turn a cosmetic bug in the
Americas into a data bug in positive-offset zones. The patcher asserts none were
touched.

## 10. Weight chart

Bounds (patch 11) — `kge` already computed these and they were never wired in:

```
pad  = (maxW - minW) * 0.1 || 5
yMin = floor(min(minW, goal) - pad)
yMax = ceil (max(maxW, goal) + pad)      // forward projection deliberately excluded
```

Period window (patch 12) — anchored on today's index as a percentage of the
rendered axis, not of the weight-data span:

```js
function __glpalWeightZoom(k, O, e) {
  const n = k && k.length ? k.length : 0;
  if (n < 2) return {start: 0, end: 100};
  const D = {week: 14, month: 30, "90days": 90}[e];
  if (!D) return {start: 0, end: 100};                 // "all"
  const t = O >= 0 && O < n ? O : n-1,
        s = Math.max(0, t - D + 1),
        x = Math.min(n-1, t + Math.ceil(D*.5));        // half-window lookahead
  return {start: s/(n-1)*100, end: x/(n-1)*100} }
```

Patch 12 also added `period` to the chart-option memo's dependency array; it was
missing, so with a short history the memo never re-ran and the chart showed a
stale period.

## 11. Dashboard

Cards, left to right: Current Weight, Start Weight, Total Loss, To Lose, BMI,
Time Active. The first five come from the dashboard grid; Time Active comes from
`Hge`, kept as a component because it closes over its `weights` prop.

Peptides and Calculator are **hidden, not removed** — filtered out of the bottom
nav (the Calculator tab's id is `"dosage"`) and the Peptide Log card is
short-circuited to `false`. Their stores and records are untouched.

Settings -> Data Management no longer shows **Load Sample Data (Demo)**
(patch 25). Upstream's button cleared every store after one `window.confirm`
and wrote demo data. The generator (`WW`, `generateSampleData`) is still in the
bundle, unreachable.

**Medication storage and dosing plans are hidden, not removed** (patches 26,
27), with `!1&&` render guards:
- Dashboard: the Medication Storage section (`bye`, including its dialog)
- Doses: the Dosing Plans section (plan list, "+ Custom Plan", "+ Schedule";
  their dialogs open only from there) and the Cost/Month, Current Dose and
  Planned Doses cards
- the Doses card grid is `lg:grid-cols-3`, holding Total Doses, Current Level
  and Logged Doses

The `protocols` and `medicationStorage` stores, their records, CSV
export/import and `Wye` are untouched. Dose records the plan feature generated
earlier (not `isManual`) still count as doses; they show without the "Manual"
label in the Log tab and can be deleted there.

Button labels (patch 28): Dashboard "+ Quick Log" reads **Weight Check-in**;
Doses "+ Log Dose Manually" reads **Log Dose**. The dialogs they open are
unchanged; the daily-log dialog's title still reads "Quick Log".

**Doses tab additions** (patches 29, 30):
- **Dosage calculator** under Log Dose (`__glpalDoseCalc`). Input: target
  medication level (mg, one decimal). Output: the dose taken now that makes the
  modelled total level peak at the target, as mg, ml and U-100 syringe units
  for 10 mg/ml and 15 mg/ml vials, plus the projected peak and its time; "No
  dose needed" if the current doses already reach the target. Since patch 31
  the four result rows sit above the input and are always shown: zeros when
  the input is empty or invalid, and "No dose needed" on the Peak row with
  zero dose rows when no dose is needed. `__glpalCalc`
  samples the next 7 days at 15-minute steps and bisects the dose, using the
  model's linearity (level = base + dose x unit curve). The new dose takes the
  medication and half-life of the most recent record.
- **Avg Peak (14d)** card (`__glpalAvgPeak`): the mean of the local maxima of
  the modelled total level in the last 336 h whose peak has already happened,
  15-minute sampling; `--` when there are none.
- Both use `__glpalLevels` / `__glpalTotalAt`, which group records exactly as
  the Current Level card does. The Doses card grid is `grid-cols-2
  lg:grid-cols-4`.

## 12. Recolour

A build stage, not a patch. `make_palette.py` maps every purple in the UI to a
muted orange (target hue from `#F58C1D`, H≈31°, saturation damped) while
**preserving WCAG relative luminance**, so every contrast ratio is unchanged.
`recolour.py` applies `palette.json` to the bundle and the CSS in every form:
`#RRGGBB` any case, `rgb()`/`rgba()` comma and space triplets, 3-digit
shorthand, and Tailwind arbitrary values like `from-[#B19CD9]`.

Accent `#B19CD9 → #D69A5A`. Background `#1A1815`. 32 colours mapped, ~726
references rewritten per build.

## 13. Service worker

Generated per build from a template in `build_fork.py`. The cache name embeds a
12-hex fingerprint of the SHA-256 of every shipped file, so any rebuild
invalidates the previous cache and installed PWAs pick up the new version on
next launch.

- install: `addAll` with `cache:'reload'`, then `skipWaiting`
- activate: delete every other cache, `clients.claim`
- fetch: GET and same-origin only; navigations network-first with cached
  `index.html` fallback; assets cache-first with network fill
- **never touches IndexedDB**

## 14. Privacy posture

- Cloudflare Insights removed from `index.html`
- Google Fonts preconnects and stylesheet removed; Inter self-hosted
- `robots.txt` Disallow all, plus a `noindex, nofollow, noarchive, nosnippet` meta
- the build asserts no external references survive, and `test_offline.py`
  asserts no request ever leaves the origin
- Google Drive backup code is present in the bundle but unused and not exposed
- health data never leaves IndexedDB on the device
